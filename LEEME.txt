SSR - Claro Ecuador | Módulo de Login (PHP + MySQL)
===================================================

INSTALACIÓN EN XAMPP
--------------------
1. Copia la carpeta "SSR_Claro" dentro de: C:\xampp\htdocs\
2. Inicia Apache y MySQL desde el panel de XAMPP.
3. Crea la base de datos "ssr_a365" y, desde phpMyAdmin (o la línea de
   comandos de MySQL), importa EN ESTE ORDEN los scripts de sql/:
     1. ssr_bd_completa.sql      (base y tablas principales)
     2. actualizacion_bd.sql     (puntaje de CV y tablas de administración)
     3. actualizacion_hu08.sql   (evaluaciones y banco de preguntas)
     4. actualizacion_avance2.sql(ajuste del Avance 2)
     5. seguridad_login.sql      (auditoría, bloqueo, cambio de clave y 2FA)
     6. correo_smtp.sql          (configuración de correo e historial)
     7. sesiones_activas.sql     (panel de sesiones activas)
     8. areas_jefe.sql           (jefe responsable por área)
     9. conectar_todo.sql        (portal público y tabla de entrevistas)
4. Revisa las credenciales de conexión en: config/conexion.php
   (por defecto XAMPP usa usuario "root" sin contraseña)
5. Revisa config/sistema.php: la ruta de las herramientas de MySQL debe
   apuntar a tu instalación (por defecto C:\xampp\mysql\bin\).
6. Abre en el navegador: http://localhost/SSR_Claro/login.php

------------------

- Consultas preparadas (PDO) contra inyección SQL.

------------------------------------------------------------
Archivo: sql/ssr_bd_completa.sql   (base: ssr_a365)

Reemplaza al esquema anterior (sql/ssr_claro.sql, que era solo login).
Importar en phpMyAdmin o MySQL Workbench.

16 tablas:
  CATÁLOGOS: areas, roles, origenes, etapas, motivos_descarte
  USUARIOS:  usuarios (con rol_id y area_id asignada)
  RECLUTAMIENTO: campanas, blacklist, postulantes (por DNI),
             postulaciones, historial_etapas
  EVALUAR:   evaluaciones, preguntas, opciones,
             resultados_eval, respuestas

Piezas clave del diseño:
  - postulantes se identifica por DNI (único).
  - postulaciones = postulante + campaña + etapa actual + reclutador
    + origen + código de seguimiento.
  - historial_etapas guarda cada movimiento con su MOTIVO de descarte
    (obligatorio si es descarte) -> alimenta el embudo de Reportes.
  - motivos_descarte están ligados a la etapa donde ocurren.
  - resultados_eval liga la nota del test a la POSTULACIÓN:
    al aprobar/reprobar, mueve o descarta la etapa automáticamente.
  - usuarios.area_id permite que cada reclutador vea solo su campaña.

Etapas del embudo (flujo real A365):
  Postulación -> Contacto telefónico -> Entrevista/Role Play ->
  Acepta propuesta -> Evaluación (test) -> Antecedentes -> Ingresa
  (la validación del DNI es automática al registrar; no es una etapa)

CAMBIOS RECIENTES (versión 1.0.x)
============================================================
0) FLUJO DEL PROCESO DE SELECCIÓN (6 ETAPAS)
   Postulación -> Evaluación (test) -> Validación (datos, CV y documentos)
   -> Entrevista presencial -> Capacitaciones (máx. 5) -> Proceso finalizado.
   - Cada paso exige cumplir el anterior (reglas en includes/flujo.php).
   - Validación: test aprobado + CV con >= 50 % de coincidencia (el sistema lo
     analiza) + datos y documentos verificados por el reclutador.
   - Entrevista presencial: el reclutador la agenda (fecha, hora, lugar) y
     luego marca que se realizó correctamente.
   - Capacitaciones: hasta 5, agendadas una a una; se registra la asistencia.
     Si no asiste a una, se descarta con el motivo "Inasistencia a
     capacitación", visible en Reportes. Si asiste a todas, finaliza el proceso.
   - Pantalla de gestión: Candidatos > ícono del ojo (proceso.php).
   - Tablero Kanban rehecho: columnas del flujo, validado en el servidor,
     Exportar (CSV), Registrar candidato, Personalizar etapas, Filtros y
     engranaje de configuración.
   - Base de datos NUEVA: ejecutar los 10 scripts de sql/ en orden
     (el último es flujo_proceso.sql).
   - Base de datos EXISTENTE (local u hosting): ejecutar UNA vez
     sql/flujo_proceso.sql desde phpMyAdmin > SQL. Es idempotente y no
     incluye USE, por lo que sirve también en el hosting.
   - La etapa externa "Validación (SARA)" ya no existe.

2) EL TEST LO RINDE EL POSTULANTE EN EL PORTAL (fuera del panel interno)
   - portal/evaluacion.php: el postulante entra con su CÓDIGO DE
     SEGUIMIENTO + DNI, responde con cronómetro y el servidor califica.
     Aprobado -> pasa a "Validación (datos, CV y documentos)". No aprobado -> Descartado con
     el motivo "No alcanzó el puntaje mínimo (70%)".
   - Tras 5 intentos fallidos de DNI en la misma sesión se bloquea el acceso.
   - Al postulante solo se le muestra su puntaje y si aprobó (no el detalle
     de las respuestas, para no filtrar el banco de preguntas).
   - El panel interno (rendir_evaluacion.php) es SOLO LECTURA: muestra el
     resultado y el detalle. Ya no hay botón para aplicar el test.
   - portal/seguimiento.php muestra "Rendir mi evaluación" mientras esté
     pendiente, y también las entrevistas programadas.

3) ALCANCE POR ÁREA PARA EL RECLUTADOR
   - El reclutador ve solo lo de SU ÁREA (usuarios.area_id): Candidatos,
     Tablero Kanban, Entrevistas, Dashboard y Reportes. Un reclutador sin
     área asignada no ve datos. Supervisor y Administrador ven todo.
   - Se valida también en el servidor: mover etapa, registrar candidato,
     programar/editar/cambiar estado de entrevistas y consultar resultados.
   - Código común: includes/alcance.php.

  filtros en rejilla, tablas con desplazamiento horizontal y vacantes del Dashboard como tarjetas.

CORREOS DE CREDENCIALES (botón "Ir al sistema")
- El botón solo se incluye con HTTPS y dominio propio (Gmail bloquea enlaces a dominios gratuitos como
  unaux.com y Chrome los marca como "Sitio peligroso"). En ese caso el correo sale sin botón.
- Cuando el sistema tenga dominio propio con HTTPS, en config/sistema.php:
    define('CORREO_URL_LOGIN', 'https://su-dominio/login.php');
    define('CORREO_INCLUIR_ENLACE', true);

SI GMAIL BLOQUEA LOS CORREOS ("mensaje sospechoso")
1) Enviar primero el "correo de prueba" (Administración → Correo). Si llega, el problema es el contenido/enlace.
2) En config/sistema.php se puede usar un correo más simple, hecho de texto (sin tiras de imagen):
    define('CORREO_DISENO', 'texto');
3) No definir CORREO_INCLUIR_ENLACE como true mientras el sistema esté en un dominio gratuito.

REPORTES: FILTRO POR FECHA Y EXPORTACION
============================================================
- Reportes > selector "desde / hasta" + boton Aplicar (atajos: Este mes, Ultimos 30 dias, Este ano, Todo).
  El filtro se aplica a TODOS los indicadores y graficas (requerimientos por fecha de creacion;
  candidatos, etapas, descartes e inasistencias por fecha de postulacion). Sin filtro = todo el historial.
  Las fechas se validan en el servidor; si desde > hasta se invierten solas.
- "Exportar Reporte" descarga un CSV (UTF-8, separador ;, abre directo en Excel) con el MISMO periodo
  y alcance (el Reclutador solo exporta su area). No requiere cambios en la base de datos.
